# Deployment Guide

## Recommended setup

Use **two deployment surfaces**:

### 1. Public portfolio demo — recommended for recruiting

Deploy `portfolio_demo.py` from a public repository.

Why:
- no OpenAI key required
- no production drama video or character assets
- no API cost generated by visitors
- shows architecture, sample output, pilot metrics, and human-in-the-loop design

### 2. Full QA app — keep private

Deploy `app.py` from a private repository/app, or run it locally.

Configure this deployment secret:

```toml
OPENAI_API_KEY = "sk-..."
```

Never commit `.streamlit/secrets.toml` or `.env`.

## Streamlit Community Cloud

1. Push the repository to GitHub.
2. In Streamlit Community Cloud, choose **Create app**.
3. Select the repository, branch, and entrypoint:
   - public demo: `portfolio_demo.py`
   - private full app: `app.py`
4. For the private full app, open **Advanced settings** and add `OPENAI_API_KEY` to Secrets.
5. Deploy.
6. For private access, keep the app private and invite specific viewers.

## Python

The code is compatible with modern Python 3.x. For Community Cloud, select a currently supported Python version in Advanced settings. Test the same version locally if you change dependencies.

## Security

- Never commit API keys.
- Do not publish real supplier content, production videos, or character assets without permission.
- A public full QA app backed by your own API key can generate uncontrolled API cost; use the synthetic demo publicly instead.
- Treat the full app as a reviewer tool, not an automated final production approval service.
